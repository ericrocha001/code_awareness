# Runtime Preview: adaptadores cooperantes

O runner interno da U2 aceita perfis aprovados `WEB_DEV_SERVER` e `ELECTRON_DEV` com `adapter.version: 1`. A seleção continua vinculada a repositoryId, worktreeId, generation e fingerprint do perfil pelo Repository Catalog/Git Operations. Esta unidade não fornece ações de UI ou Channel para start/stop.

O comando aprovado deve apontar para o Node fixado e receber somente o caminho do SDK `scripts/runtime-preview/launch.cjs`. O checkout deve conter cópias exatas de launch/cooperation do SDK confiável configurado pelo host. O perfil declara kind (`VITE_WEB`, `NODE_WEB`, `ELECTRON`), configFile, porta e artefatos por componente. Electron também exige executável e SHA-256 próprios. Os arquivos, dependências e runtime devem estar fisicamente na Worktree, sem empréstimo de node_modules da main.

Declare em nativeModules todos os pacotes instalados com hasInstallScript no lockfile npm. A importação desses módulos no runtime real ocorre sob o mesmo Job antes do permit persistido; SQLite também executa uma consulta. Pacotes opcionais ausentes são admitidos pela regra da U1. Instalar ou reconstruir dependências exige uma operação separada autorizada. UNKNOWN de outro motivo permanece bloqueado; o preflight não é reclassificado por suposição. A prova dinâmica tem escopo DECLARED_INSTALL_SCRIPTS e não atesta código arbitrário nem toda operação futura da aplicação.

O Vite deve incluir vitePreviewPlugin() de cooperation.cjs antes de plugins que transformem os inputs relevantes, incluindo React. O Electron deve incluir buildIdentity() para main e preload e inicializar a proteção de preview antes de importar singletons de domínio. O Code Awareness implementa isso em bootstrap.ts. Worktrees antigas sem cooperação não recebem patches automáticos. NODE_WEB é um adaptador HTTP mínimo para uma aplicação cooperante com um artefato JS WEB, sem dependências adicionais; não interpreta comandos livres.

Recursos privados incluem diretórios de app/user/session, home/temp, caches e a porta loopback declarada. O bootstrap de preview não registra protocolo Windows, não adquire o lock canônico e não inicia LocalAgentChannel ou MCP. O sandbox Chromium permanece habilitado. Isolamento de perfil não é contenção de segurança de código malicioso: exigências de enforcement não disponíveis continuam bloqueadas pela U1.

Cada inspect verifica identidade Git/perfil, ownership TCP nativo e evidência cooperante com desafio novo. sourceSnapshot conserva o lançamento; sourceObservation representa a consulta corrente. Os componentes main, preload e renderer têm evidências independentes de transformação e inicialização. Os escopos são exclusivamente os caminhos declarados: loadedCode VERIFIED não significa que todos os módulos do aplicativo foram atestados. Main/preload não servidos por HTTP podem manter artifact UNVERIFIABLE e loadedCode VERIFIED. Componente sem prova conserva UNVERIFIABLE. HMR de renderer não atualiza main/preload; mudanças nestes exigem RESTART_PREVIEW_REQUIRED, sem restart automático.

Stop exige drenagem nativa, fechamento de handles e liberação dos recursos próprios. Recuperação com recibo DRAINED também testa a disponibilidade da porta; ocupação posterior preserva CLEANUP_INCOMPLETE, nunca autoriza matar o novo listener. Sem prova nativa terminal, preserva OWNERSHIP_UNVERIFIED. O limite de recibos encerra a observação com incerteza em vez de retornar atestação antiga como atual.

Provas locais: `node scripts/runtime-preview/acceptance.cjs node-web` ou `electron`, em Windows com dependências preparadas, usa catálogo/control store privativo e Git/runner/Job reais. Os comandos stdin são inspect e stop; as opções --wrong-abi e --port-collision exercitam negativas. --faults habilita somente no binário de teste a injeção de crash de renderer, condicionada a PID, criação e membership do Job. O binário de produção não contém essa ação. As evidências ficam em .code-awareness/u3; os recursos operacionais de cada sessão ficam fora do checkout. Execute os cenários nativos serialmente, pois a compilação não substitui um helper que ainda está em uso no Windows.
